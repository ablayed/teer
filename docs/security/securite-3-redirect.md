# SEC-C-003 — plan du correctif ciblé

Cause : safeRedirectPath contrôlait slash et antislash, mais pas les caractères ASCII de contrôle supprimés par le parseur URL. Deux slashes séparés par une tabulation, LF ou CR pouvaient ainsi devenir une autorité externe. Le callback utilise ensuite new URL avec cette chaîne. Le garde local distinct de lib/actions/legal.ts doit utiliser la même barrière, en conservant son exclusion de /reacceptation.

Plan : refuser les contrôles ASCII et DEL, maintenir les rejets existants, vérifier l'origine après parsing sur une origine fixe sans réseau ; conserver les chemins et paramètres internes légitimes. Tester le helper partagé et le callback avec des Request synthétiques, sans suivre de destination distante ni utiliser une session réelle. Aucun nouveau test d'exploitation sur serveur ou production ; les cas négatifs sont des régressions unitaires du contrat de redirection. Puis sanity complète, revue du diff, PR distincte et deux CI initiales sur SHA final, fusion conditionnellement autorisée par le porteur.

Risques UX : les liens internes contenant des contrôles littéraux retombent sur /tableau. Les espaces encodés, recherches, ancres, chemins boutique et retours de consentement normaux restent autorisés. Pas de modification de cookies, session, OAuth ou fournisseur Auth. Revenir sur le commit dans une PR relue réouvrirait la faille ; pas de migration SQL.

Validation locale du 12 novembre, base main ba65224 : typecheck/lint/build et invariants ACL/service-role verts ; 2 079 unités passantes, trois ignorées préexistantes ; 812 RLS passantes. Les 14 nouvelles régressions vérifient les chemins internes, les rejets antérieurs, les 32 contrôles ASCII et DEL dans un test borné, les trois cas tab/LF/CR dans le vrai callback appelé avec une Request synthétique, et le maintien des paramètres/ancres. Aucun HTTP vers une cible distante, aucun suivi de redirection externe, aucune session réelle utilisée. Les anciens tests et timeouts sont inchangés. Preuves locales : security-audit-proofs/docs/security/evidence/s3-c003-*.

Revue du diff : le parcours de caractères utilise une mémoire auxiliaire constante ; l'origine fixe sert au seul parsing URL. Le garde partagé remplace le doublon légal et conserve son exclusion de /reacceptation. Risque résiduel : les autres consommateurs doivent continuer d'appeler ce garde ; la protection ne couvre pas des chaînes de redirections issues d'autres endpoints non inspectés. La fusion reste subordonnée au rebase final, à CLEAN et aux deux nouvelles CI initiales du même SHA ; aucune migration ni configuration distante.

Recontrôle après rebase sur main b800426 (HTTP positifs et bornage Zod 3 fusionnés) : **2 085 unités passantes, trois ignorées préexistantes, 812 RLS passantes**, typecheck/lint/build et deux invariants verts.
